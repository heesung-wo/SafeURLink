# SafeURLink v0.6.9 — 하루 1회 자동 갱신

이 수정본은 **사용자가 업로드한 v0.6.7 프로젝트**에만 기반합니다. v0.6.8에서 추가한 별도 메타 피드 기능은 포함하지 않습니다. GitHub Actions 워크플로는 변경하지 않았습니다.

## 동작

- GitHub Actions: 기존 설정 그대로, 매일 **12:17 KST경** 각 외부 API에서 수집한 데이터를 GitHub Pages에 배포합니다.
- 확장 프로그램: `https://heesung-wo.github.io/SafeURLink/signatures.json`을 **매일 15:00 KST**에 확인합니다.
- 브라우저가 그 시각에 종료되거나 절전 중이었다면 다음 브라우저 실행 시 누락된 확인을 수행합니다.
- 한 예약 주기의 다운로드·DB 반영을 정상 완료하면 재실행해도 중복 확인하지 않습니다.
- 확인이 실패하면 기존 시그니처를 보존하고, 브라우저가 실행 중일 때 **1시간 후 재시도**합니다. 브라우저가 꺼져 있으면 재시도 시각 이후 첫 실행에 재시도합니다.
- **지금 업데이트** 버튼은 일일 자동 확인과 별개로 동작하며, 기존 1분 쿨다운을 유지합니다.
- 최초 설치로 성공 기록이 없다면 예약 시각을 기다리지 않고 우선 피드 다운로드를 시도합니다.

## 적용

1. 패치 ZIP의 `safe-ur-link/` 파일을 기존 확장 프로그램 폴더에 **덮어씁니다**.
2. 기존 확장 프로그램을 **삭제하지 말고** `chrome://extensions` 또는 Whale 확장 관리 페이지에서 새로고침합니다. 삭제 후 재설치하면 IndexedDB가 사라질 수 있습니다.
3. 설정 화면의 **다음 확인**, **마지막 피드 확인 성공**, **마지막 새 피드 적용**을 확인합니다.
4. 일정 변경은 `core/daily-sync.js`의 `DAILY_SYNC_HOUR_KST`와 `DAILY_SYNC_MINUTE_KST`를 조정합니다.
5. **GitHub Actions 워크플로 변경이나 재배포는 필요하지 않습니다.** 다만 변경된 `core/` 파일을 GitHub `main`에 올리면 기존 워크플로의 `push.paths` 때문에 Actions가 자동으로 실행될 수 있습니다.

## 제한 사항

- 예약 알람은 브라우저를 강제로 실행하거나 종료된 브라우저에서 네트워크 요청을 보낼 수 없습니다.
- GitHub Actions 배포 지연 등으로 오후 3시에 아직 새 피드가 없다면 동일한 공개 피드를 정상 확인한 것으로 처리합니다. 새 피드는 다음 정기 확인 또는 수동 업데이트에서 적용됩니다.
- v0.6.7의 기존 방식과 마찬가지로 확인할 때마다 전체 `signatures.json`을 다운로드합니다. 약 100만 건 규모의 실측 성능이나 브라우저의 중단·메모리 오류까지 이 테스트에서 보증하지 않습니다.
- **일일 예약 주기별** 확인을 보장하도록 설계되어 있습니다. 어제 놓친 확인을 오늘 오전에 보충한 경우, 오늘 오후 3시 정기 확인도 별도로 발생할 수 있습니다(서로 다른 날짜의 예약분).
- 브라우저 또는 운영체제가 절전 중인 경우 정각보다 실행이 늦어질 수 있습니다.
